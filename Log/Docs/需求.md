# Log 需求

用户目标：用静态类和静态方法封装 Unity 日志，支持输出开关与级别控制。以下默认值、等级和会话规则为本轮技术规划，尚未实现。

## 行为与验收

| 情境与前提 | 要求与可判定结果 |
|---|---|
| 调用与配置 | 输出、配置及查询均为静态方法，无需实例、组件或显式初始化；模块持有一份供所有消费者共用的配置。 |
| 开关与等级 | 采用 `Info < Warning < Error` 最低阈值，关闭时连异常也不转发，组合见下表。设置或查询非法等级均抛 `ArgumentOutOfRangeException`，配置不变。 |
| 运行时修改 | 各构建类型均可反复修改，完成后对后续调用生效；重新开启保留阈值，不缓存或补发被过滤日志。 |
| 初始状态与会话 | 默认开启、阈值为 `Info`；每次应用运行及新 Play 会话恢复默认，包括关闭 [Domain Reload](https://docs.unity3d.com/6000.0/Documentation/Manual/domain-reloading.html)。宿主随后应用自选配置，模块不按构建类型改写策略。 |
| 普通日志 | 原消息及可选 Unity 对象上下文分别交给 `Debug.Log`、`LogWarning`、`LogError`，保留级别和对象定位，不加前缀或改写；`null`、空字符串沿用 Unity 语义。 |
| 异常报告 | 按 `Error` 过滤，将原异常和可选上下文交给 `Debug.LogException`，保留类型及原始堆栈。空异常始终抛 `ArgumentNullException`，不受开关影响。 |
| 过滤与查询 | 被过滤时不调用 Unity 输出或消息的 `ToString()`；传参前已发生的插值、拼接、构造不在保证内。`IsEnabled` 只查询本模块当前开关与阈值；输出时仍重新判断，不缓存查询结果。 |
| 输出边界与失败 | 只控制本模块入口，不修改 Unity 的 `logEnabled`、`filterLogType` 或全局处理器，不影响其他直接日志。Unity 全局配置及 Console 过滤仍可影响可见性；放行或查询为真不保证显示。底层抛错原样传播，不通过自身入口递归报告。 |

“输出”指包装层放行并转发 Unity：

| 总开关 | 最低级别 | Info | Warning | Error / 异常 |
|---|---|---|---|---|
| 关闭 | 任一合法级别 | 不输出 | 不输出 | 不输出 |
| 开启 | Info | 输出 | 输出 | 输出 |
| 开启 | Warning | 不输出 | 输出 | 输出 |
| 开启 | Error | 不输出 | 不输出 | 输出 |

模块入口：[Log](../README.md)。
