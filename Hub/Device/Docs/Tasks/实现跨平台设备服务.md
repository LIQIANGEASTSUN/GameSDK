## 公开契约与组装

`GameInterface/IDevice.cs` 只依赖通用 C# 类型，命名空间为 `GameInterface`，公开契约完整如下：

```csharp
using System.Collections.Generic;

public interface IDevice
{
    string GetDeviceId(Dictionary<string, object> parameters = null);
    string GetAdvertisingId();
    bool GetAdvertisingTrackingEnabled();
    void DeleteIosDeviceId(Dictionary<string, object> parameters = null);
}
```

GameSDK 的公开类型使用 `GameSDK` 命名空间：

```csharp
public static class DeviceService
{
    public static GameInterface.IDevice Create();
}
```

以上签名描述应交付的 API，不依赖现有实现。工厂不接收、构造或校验 iOS 配置，不提供其他公开配置入口。Android 与 Fallback 的设备 ID/删除方法忽略参数字典，包括 `null` 或内容无效的字典；只有 iOS 在这两个方法中解析本次参数。广告方法不接收字典，也不依赖先前是否成功调用设备 ID 方法。

`Create` 必须由 Unity 主线程调用，这是使用前置条件；工厂不承诺从任意线程自动识别 Unity 主线程。工厂每次无参创建一个新实例，不设置全局实例、不读取标识、不访问 Keychain、不申请权限，不需要显式初始化或释放。选择顺序固定为：`UNITY_EDITOR` 优先使用 Fallback；否则 `UNITY_ANDROID` 使用 Android；否则 `UNITY_IOS` 使用 iOS；其余使用 Fallback。`DeviceIOS` 使用无参构造，不保存参数字典或配置。只有 Android 实例记录创建线程 ID，供其广告方法拒绝主线程调用。平台实现类型为内部类型，消费者不能据平台选择或创建它们。

项目组合入口创建实例；调用方在每次需要 iOS 设备标识时传入稳定定位参数，字符串不能每次随机生成：

```csharp
using System.Collections.Generic;
using GameInterface;
using GameSDK;

IDevice device = DeviceService.Create();
var parameters = new Dictionary<string, object>
{
    ["account"] = "project-device",
    ["service"] = "com.example.game.device",
    ["identifier"] = "install-id",
    ["description"] = "Game device identifier"
};
string deviceId = device.GetDeviceId(parameters);
```

示例必须在 Unity 主线程执行。接口实例由项目组合入口持有并注入消费者；不新增隐式注册机制。标识值不能作为日志内容。仅在项目明确要求重置时调用 `device.DeleteIosDeviceId(parameters)`，使用与目标项相同的三项定位值，不能放在普通退出或实例释放流程。

### iOS 参数解析与归属

`IOSKeychainOptions` 是内部不可变类型：构造函数为私有，只读字符串属性为 Account、Service、Identifier、Description；唯一解析入口为 `internal static IOSKeychainOptions FromParameters(Dictionary<string, object> parameters)`。`DeviceIOS.GetDeviceId` 和 `DeleteIosDeviceId` 每次先调用该入口，全部校验成功后再使用本次局部配置进入原生桥接，失败前不能访问 Keychain。

| 输入 | 规则与错误 |
|---|---|
| 整个字典为 `null` | 抛 `ArgumentNullException`，`ParamName` 为 `parameters`。 |
| `account`、`service`、`identifier` | 三个键必需，值必须是非空、非纯空白且不含 NUL 的字符串；缺键、`null`、非字符串或不合法内容均抛 `ArgumentException`，`ParamName` 为 `parameters`。 |
| `description` | 缺键时为 `string.Empty`；提供时必须为不含 NUL 的字符串，允许空或纯空白。提供 `null`、非字符串或含 NUL 值时抛 `ArgumentException`，`ParamName` 为 `parameters`。 |
| 未知键 | 忽略，不验证其值；不得因此覆盖或补造已知键。 |

直接对传入字典使用四个约定键执行 `TryGetValue`，遵循该字典的比较器语义，不复制成另一套键比较规则；有效字符串原样保存，不 trim、不改变大小写或 Unicode。参数错误消息可指明出错键，不能包含字典中的值。

调用方拥有字典，方法执行期间不得并发修改。内部仅保存本次解析得到的局部不可变字符串；后续调用方修改字典不会改变已解析的配置，每次新调用则重新读取当次内容，不能串用上次配置或保留字典引用。调用方要访问同一 Keychain 项，必须每次传入相同 Account、Service、Identifier；Description 只影响缺项后的新建。不给缺失参数生成默认值，不从 `Application.identifier` 派生键，也不引入配置中心。

## 线程、重复调用与错误边界

- `GetDeviceId`、`DeleteIosDeviceId` 以及 iOS/Fallback 的广告方法，由调用方保证在 Unity 主线程调用；实现不再使用通用线程守卫主动拒绝，不承诺跨线程必抛或任意线程安全。
- Android 两个广告方法必须在工作线程调用，并共用 `ReadAdvertisingId` 查询入口。Android 实例只保存其创建线程 ID；该入口先拒绝创建线程，再通过 JNI 检查 Java UI 线程，两者都须在调用 Google 服务前抛 `InvalidOperationException`。当前 Looper 为 `null` 表示不是 Java UI 线程，主 Looper 缺失则报错；检查中的临时 JNI 对象同样须完整释放。不加锁、内部任务、等待或调度。宿主安排工作线程并接收结果；其他 Unity 操作仍回主线程执行。
- Android 广告的整段 JNI 操作使用 `AndroidJNI.InvokeAttached` 包裹，临时 `AndroidJavaClass`、Activity、Context 与返回包装对象均在本次调用结束释放，异常路径同样释放。不得把临时 Activity 缓存在实例中。广告调用入口直接使用 `try/catch` 和 Unity 的 `InvokeAttached(Action)`，回调只调用具名 `ReadAdvertisingIdCore` 并回填本次局部结果，不套自定义 `Invoke<T>(Func<T>, ...)` 或将整段查询放入匿名函数。该 Unity 入口同步维护当前线程的 JNI 附着，不创建或切换线程，也不将结果保存到实例字段；设备 ID 的 Unity 属性读取不经过本模块 JNI 路径。
- 各次调用独立读取当前平台结果，不缓存设备 ID 或广告结果。两个广告方法各自查询，不保证跨调用快照一致。实例不持有长期原生资源，无 `IDisposable`；Android 广告的线程检查不意味着宿主可跨线程访问其他 Unity API。
- 参数错误使用前述参数异常；Android 广告主动拒绝线程或设备 ID 返回不可用值时使用 `InvalidOperationException`；平台/JNI/原生访问失败向消费者报告 `InvalidOperationException`，可取得的托管或 Java 异常保留为 `InnerException`，Keychain 错误包含 OSStatus 和操作名。错误消息不得包含设备 ID、广告 ID 或 Keychain 值。不把异常降级成随机 ID、空值或成功。
- 广告受限、空 ID 或全零 ID，以及 Fallback 平台无广告能力，是正常不可用结果，分别为 `string.Empty` 与 `false`；Google 库缺失或服务连接失败属于错误，不与上述结果混同。

## Android 实施规则

### Unity 设备标识与支持边界

当前工程是未出包 Demo，无需兼容参考实现的 64 字符设备 ID。Android 最低支持版本为 8.0/API 26，按[项目定义](../../../../../../Docs/Project/01_项目定义.md#已确认的边界)设置 `ProjectSettings/ProjectSettings.asset` 中 `AndroidMinSdkVersion = 26`；不为 Android 6/7 增加运行时分派或兼容路径。

`DeviceAndroid.GetDeviceId` 每次直接读取一次 `SystemInfo.deviceUniqueIdentifier`，调用方负责在 Unity 主线程执行，仍忽略参数字典。读取结果为 `null`、空字符串或等于 `SystemInfo.unsupportedIdentifier` 时抛 `InvalidOperationException`，错误消息不包含该值；其余值原样返回，不 trim、不改变大小写、不按 32 或 64 字符长度筛选。本模块不缓存、拼接签名、再次哈希或通过 JNI 获取设备 ID，不为这次属性读取增加抽象、替身或独立算法类型。此拒绝规则仅用于 Android；Fallback 仍保留原样返回不支持标识、仅将 `null` 变为空字符串的行为。

[Unity 6 官方文档](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/SystemInfo-deviceUniqueIdentifier.html)说明 Android 上该属性返回 `ANDROID_ID` 的 MD5。这里是 Unity 的平台行为说明，本模块只消费属性，不自行实现 MD5 或承诺固定字符串格式。调试签名、正式签名及 Google Play 最终签名不同可能导致不同值。

[Android ANDROID_ID 规则](https://developer.android.com/reference/android/provider/Settings.Secure#ANDROID_ID)将 Android 8.0+ 的值限定到设备、用户和应用签名组合；恢复出厂或签名变化可能改变值，切换用户也不能视为同一标识。[Android 8.0 隐私变更](https://developer.android.com/about/versions/oreo/android-8.0-changes#privacy)说明同设备、同用户、同签名的普通卸载重装不改变该值，但在 OTA 升级到 Android 8.0 之前已安装的应用，升级后再卸载重装存在变化例外。因此只要求上述普通重装场景稳定，不承诺永久唯一，也不为当前 Demo 引入旧 ID 迁移或服务端历史关联。

删除 `Runtime/Internal/AndroidDeviceId.cs` 及元数据、`Plugins/Android/AndroidIDPlugin.java` 及元数据，并删除因此为空的 `Plugins/Android` 目录与目录元数据；保留 `Plugins/iOS`。移除旧哈希测试及其反射辅助，保留其他工厂、Fallback 和 iOS 参数测试，不用旧哈希结果证明新读取实现。

### 广告查询与插件交付

C# 完成线程检查后，通过 JNI 取得 `UnityPlayer.currentActivity` 的 Application Context，并直接访问 `com.google.android.gms.ads.identifier.AdvertisingIdClient.getAdvertisingIdInfo(context)`；不增加 Java 广告桥接，也不向契约暴露 Java/Google 类型。Info 缺失属于查询失败，抛错。每次取得 Info 后读取 `isLimitAdTrackingEnabled()` 与 `getId()`：只有限制标志为 `false` 且 ID 非空、非全零时为可用，否则隐藏该 ID，返回空字符串 / `false`。全零包括标准全零 UUID；判断不能把大小写或连字符形式差异视为有效 ID。非全零有效 ID 原样返回。

Google 广告能力属于宿主接入前提：宿主现有依赖管理须提供 `com.google.android.gms:play-services-ads-identifier` 的兼容版本（接口基线 `18.3.0`），最终合并 Manifest 须具有 `com.google.android.gms.permission.AD_ID`，并在使用代码压缩时保留 JNI 访问的类名与方法。本模块不创建 `.androidlib`、Gradle、Manifest 或 `consumer-rules.pro`，不自动下载、解析或配置这些依赖。宿主未提供 Google 库或设备没有可用 GMS 时，设备 ID 仍可独立使用，广告查询明确失败；由于权限或平台限制得到全零广告 ID 时按合法不可用结果处理。

宿主开启 R8/ProGuard 时，最少须覆盖下列广告 JNI 入口；可合并到宿主既有裁剪方案，不要求在本模块生成配置文件。Unity 设备 ID 读取不再需要自定义插件保留规则：

```proguard
-keep class com.google.android.gms.ads.identifier.AdvertisingIdClient {
    public static com.google.android.gms.ads.identifier.AdvertisingIdClient$Info getAdvertisingIdInfo(android.content.Context);
}
-keep class com.google.android.gms.ads.identifier.AdvertisingIdClient$Info {
    public java.lang.String getId();
    public boolean isLimitAdTrackingEnabled();
}
```

`DeviceAndroid.cs` 整个文件只用一组 `#if UNITY_ANDROID && !UNITY_EDITOR` 与末尾 `#endif` 包裹，所有 using、命名空间和 Android 实现均在其中。Editor 即使切到 Android 构建目标仍使用 Fallback，不触发 Android 广告 JNI 路径。`DeleteIosDeviceId` 忽略参数字典，无副作用返回。

## iOS 实施规则

### Keychain 定位与状态转换

使用 `kSecClassGenericPassword`。查询字典固定包含 Account 对应 `kSecAttrAccount`、Service 对应 `kSecAttrService`，以及 Identifier 的 UTF-8 字节对应 `kSecAttrGeneric`。查询、添加和删除使用相同定位条件；Description 仅在创建时写入 `kSecAttrDescription`，不参与查找。保持系统默认的可访问性、访问组与同步设置，不擅加新的 `kSecAttrAccessible`、`kSecAttrAccessGroup` 或 `kSecAttrSynchronizable` 值。

GenericPassword 的主要唯一性由 Account 与 Service 等系统属性决定，Generic 不是独立唯一键。因此相同 Account/Service、不同 Identifier 可能发生“查无项但添加冲突”；禁止通过删除不匹配项来解决。需要独立命名空间时项目使用不同 Account 或 Service。迁移旧数据时固定沿用三项定位字符串，不能用新默认值替换。

| 操作与结果 | 下一步与终态 |
|---|---|
| `SecItemCopyMatching` 成功，值为非空、不含 NUL 的有效 UTF-8 | 原样返回，不检查其是否为 UUID，不改写元数据；改变 Description 不影响已存在项，只有后续新建时使用新 Description。 |
| 查询成功但值为空、不是 Data、不是有效 UTF-8 或含嵌入 NUL | 按解码损坏失败报告（`errSecDecode`），不删除、不创建、不覆盖；不能让 C 字符串封送把含 NUL 的值截断后当作成功。 |
| 查询返回 `errSecItemNotFound` | 生成一个大写带连字符 UUID，将 UTF-8 数据、Description、创建时间与修改时间作为新项一次性添加。 |
| 添加成功 | 返回实际已保存的 UUID；分配返回缓冲区失败时报错，已保存项保留，后续读取可恢复。 |
| 添加返回 `errSecDuplicateItem` | 按原条件重新查询一次；读到合法现存值则返回该值。仍找不到、损坏或其他错误则报告实际状态，不返回本次未保存 UUID，不删除冲突项，不无限重试。 |
| 查询或添加返回其他 OSStatus | 立即报告该错误，不把访问限制、锁定或权限错误当作缺项；不修改已有数据。 |
| `SecItemDelete` 成功或返回 `errSecItemNotFound` | 视为成功，重复删除安全；无缓存需要清除，随后正常读取遵循上面的查询/创建流程。 |
| 删除返回其他 OSStatus | 报告删除失败，不伪造成功，不自动生成新项或删除更宽范围。 |

由于实例不缓存标识或配置，同一实例或不同实例只要本次传入相同三项定位参数，就观察同一 Keychain 当前值；任一实例成功删除后，其他实例以相同参数再次读取也须重新查询并遵循创建流程。读取/删除的每次操作本身完成后返回；本接口不提供跨实例事务或一组操作的锁定，业务不得依赖读取和随后删除之间的原子性。

### 原生桥接和内存

`GameSDKDevice.mm` 使用 ARC、Foundation 与 Security。内部执行上面的查询/必要创建，导出带 `GameSDKDevice_` 前缀的 C 函数，托管以 `DllImport("__Internal")` 调用。接口采用 OSStatus 整数返回码和 `out IntPtr` UTF-8 缓冲区，不直接将拥有所有权的字符串声明为自动封送的托管 `string` 返回值：

- `GameSDKDevice_GetDeviceId(account, service, identifier, description, out value)`：成功为 0，返回本次分配的非空 UTF-8 缓冲区；失败返回原始或对应 Security 错误，输出指针初始化为空。
- `GameSDKDevice_DeleteDeviceId(account, service, identifier)`：成功/不存在归一化为 0，其他失败返回 OSStatus。
- `GameSDKDevice_GetAdvertisingInfo(out value, out enabled)`：成功为 0；受限或无有效 ID 返回空值与 `enabled = 0`，可用返回 ID 与 `enabled = 1`。分配等原生失败返回非 0。
- `GameSDKDevice_FreeString(value)`：释放该桥接分配的缓冲区，空指针安全。

原生返回字符串用明确分配的、NUL 结尾 UTF-8 缓冲区交给托管方；托管方复制字节为托管字符串，并在 `finally` 中对所有非零返回指针恰好释放一次，包括复制或状态处理抛错时。原生 `Copy`/`Create` 获得的 Core Foundation 资源在所有路径释放或正确转交 ARC，分配失败报告 `errSecAllocate`。任何层都不记录 UUID、IDFA 或 Keychain 内容。

托管 `GetDeviceId`、`DeleteIosDeviceId` 和 `ReadAdvertisingInfo` 直接处理原生调用与异常，不使用自定义 `InvokeNative<T>(Func<T>)` 或外层 lambda。两个设备 ID 方法先在原生异常捕获区外解析本次参数；`GetDeviceId` 与 `ReadAdvertisingInfo` 使用外层 `try/catch` 包住内层 `try/finally`，内层负责调用、状态处理、字符串复制和非零指针释放。外层捕获范围必须包含 `finally` 中的 `GameSDKDevice_FreeString`，不能改成同层 `try/catch/finally` 而让释放异常绕过转换。删除方法直接 `try/catch` 执行原生删除及状态处理，不构造无用途的返回值。

上述三个入口仅将 `DllNotFoundException`、`EntryPointNotFoundException`、`BadImageFormatException` 转换为消息为 `iOS device bridge is unavailable.` 的 `InvalidOperationException`，并保留原异常为 `InnerException`；读取或释放阶段发生这三类异常均遵循此规则。参数异常，以及状态检查或空指针检查产生的 `InvalidOperationException` 保持原样，不重复包装。保留既有原生符号、参数封送、返回值与资源归属，不为这次结构调整引入新的助手类型或测试替身。

### 广告状态和构建

iOS 14 及以上仅在 `ATTrackingManager.trackingAuthorizationStatus == ATTrackingManagerAuthorizationStatusAuthorized` 时允许 IDFA；Denied、Restricted、NotDetermined 都返回空字符串 / `false`。iOS 13 使用 `ASIdentifierManager.isAdvertisingTrackingEnabled`。同时要求广告 ID 字符串非空、非全零 UUID；任一条件不满足均不返回标识。两个公开广告方法每次独立调用此原生查询，不申请 ATT 权限，也不添加权限弹窗流程。

插件只用于 iOS Player，通过本文件 PluginImporter 的 `CompileFlags = -fobjc-arc` 启用 ARC，不修改其他插件的编译选项。构建链接 Foundation、Security、AdSupport，并弱链接 AppTrackingTransparency，使用系统版本可用性判断后才能访问 ATT。Editor 构建后处理对实际包含插件的 UnityFramework 目标添加所需链接，重复导出或重复处理不能累积无效条目；编辑器专用程序集隔离 `UnityEditor.iOS.Xcode` 依赖。项目若需要申请 ATT，应在自己的产品流程设置用途说明并发起请求，本模块不会以读取方法隐式申请。

## Fallback 与包接线

Fallback 每次从 `SystemInfo.deviceUniqueIdentifier` 读取原值，包括 `SystemInfo.unsupportedIdentifier`；仅 `null` 返回 `string.Empty`。读取和删除均忽略参数字典；广告方法固定返回 `string.Empty` / `false`，删除无副作用返回，不另加主动线程检查。没有其他平台宏时也可创建该实现，不能留下未赋值实现导致空引用。

`GameInterface` 保持不依赖 UnityEngine 或 GameSDK；`GameSDK.asmdef` 引用 `GameInterface`，`GameSDK/package.json` 的 `dependencies` 声明 `"com.liqiangeastsun.gameinterface": "0.1.0"`，与当前 `GameInterface/package.json` 的已交付版本一致。运行时代码不新建逐功能 asmdef；Editor 和 Tests 使用各自隔离程序集。平台条件编译、插件导入平台、文件/目录 `.meta` 与稳定 GUID 一并交付；不改变无关包结构或用户已有修改。包声明只完成接线，仍须由 Unity 实际解析并验证依赖版本；`Packages/packages-lock.json` 由 [UPM 维护](https://docs.unity3d.com/6000.0/Documentation/Manual/upm-conflicts-auto.html)并按实际解析结果刷新，不手工改写锁文件代替验证。

### iOS 边界场景的可执行方法

在导出的 Xcode 测试构建使用临时原生测试源或 LLDB，所有操作只针对独立测试 Account/Service。测试用 native 输入和故障注入不进入发布产物，不改项目正式 Keychain 值；无需为此另建验证框架或报告。

1. **历史值与损坏数据：** 用与生产相同的三项定位条件构造 GenericPassword 字典，仅清理该测试键后，用 `SecItemAdd` 的 `kSecValueData` 分别写入 `legacy-value` 的 UTF-8 Data、长度 0 的 Data、字节 `{ 0xFF }`、字节 `{ 0x61, 0x00, 0x62 }`。通过真实工厂获得 `IDevice`，将同三项测试定位值放入参数字典传给 `GetDeviceId(parameters)`；第一个原样返回，其余报告 `errSecDecode`。随后用 `SecItemCopyMatching` 直接比对原 Data 未改变。用新字典仅改变 description 再读不能改变原值；每组完成后只清理自己的测试键。
2. **两类添加冲突：** 相同 Account/Service、不同 Identifier 用真实 `SecItemAdd` 建第一项，再将第二套定位参数字典传给公开 `GetDeviceId`，预期查询缺项、添加冲突、重读仍缺项并报错，第一项保持原值。要验证重复项重读成功，在原生读取流程首次 `errSecItemNotFound` 之后、添加之前设断点；暂停时用 LLDB 或另一个原生执行者以相同定位条件先写入 `concurrent-value`，再继续生产流程，应返回这一已保存值。第二写入者不要复用同一断点，避免测试死锁；不能用 Unity 主线程串行调用两次托管 API 冒充该竞态。
3. **指定失败状态与禁止副作用：** 仅在原生测试构建将 `SecItemCopyMatching`、`SecItemAdd`、`SecItemDelete` 经可控包装函数转发到真实系统 API，并按指定调用序号注入 `errSecInteractionNotAllowed`、`errSecAuthFailed` 等非缺项状态。查询失败后不得执行 Add/Delete；添加失败不得返回未保存 UUID；删除失败不得继续 Get/Add。断言返回 OSStatus、托管异常映射、操作次数及原 Data，恢复转发后重复正常调用应可恢复。这验证错误分支与映射，不能称为真实锁屏或权限配置已经通过。
4. **真实受保护数据场景：** 使用已设置锁屏密码的 iOS 测试设备；无密码设备不能证明锁定保护。专用测试项设为 [`kSecAttrAccessibleWhenUnlocked`](https://developer.apple.com/documentation/security/ksecattraccessiblewhenunlocked)，测试宿主启动有限的 iOS background task，锁屏直至 `UIApplication.protectedDataAvailable == NO` 后在主 dispatch 队列调用原生设备读取，观察实际 OSStatus；预期访问被拒时报告 `errSecInteractionNotAllowed`（-25308），不得创建替代值，解锁后原值仍可读。结束后归还 background task。该步骤只验证真实读取限制，不推断 Delete/Add 必然受同样限制；托管异常映射和指定写/删失败由上项另验。系统、调试器或后台时限导致无法到达场景时，记录实际现象及未执行/未覆盖，不把状态注入当作本项通过。权限/访问组真实拒绝仅在有可控测试签名和 entitlement 的环境中按相同原则验证，不宣称所有设备必然产生同一种拒绝。

测试中涉及真实广告信息或平台 ID 时仅断言结果，不输出原文。删除、损坏数据、定位冲突与失败注入均使用专用测试 Account/Service，禁止用项目正式历史 ID 做破坏性验证；历史迁移只读查询并比对，只有用户明确主动删除场景才删除正式项。修改系统设置、广告授权、签名或构建配置后，应记录对应场景与期望，不将无关旧运行结果复用为本次通过。必要项通过且未参与该产物实现的 Agent 完成独立检查后，才能将整项标为 `Done`。
