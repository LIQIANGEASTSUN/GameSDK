# EventBus 需求

提供可直接通过单例调用、显式注册和注销的类型化事件总线，事件标识使用 `string`，兼顾发布、注册及注销性能。本文的 API 是待实现目标。

## 公开 API 与归属

`EventBus` 的公开方法与实现均归 GameSDK。允许引用 GameSDK 的上层业务、Hub 模块及 SDK 自身模块直接使用 `EventBus.Instance.Subscribe(...)`、`EventBus.Instance.Unsubscribe(...)`、`EventBus.Instance.Publish(...)`，无需事件总线接口或接口注册、注入与实现。

`Instance` 表示本模块目标单例获取形式；实际获取与生命周期钩子须等前置单例交付后对齐，不代表已有 API。

三种操作各提供无参、1 参、2 参、3 参四个重载，共 12 个，全部返回 `void`；参数数量指业务参数，不计事件名 `key`：

```csharp
void Subscribe(string key, Action callback);
void Subscribe<T1>(string key, Action<T1> callback);
void Subscribe<T1, T2>(string key, Action<T1, T2> callback);
void Subscribe<T1, T2, T3>(string key, Action<T1, T2, T3> callback);

void Unsubscribe(string key, Action callback);
void Unsubscribe<T1>(string key, Action<T1> callback);
void Unsubscribe<T1, T2>(string key, Action<T1, T2> callback);
void Unsubscribe<T1, T2, T3>(string key, Action<T1, T2, T3> callback);

void Publish(string key);
void Publish<T1>(string key, T1 arg1);
void Publish<T1, T2>(string key, T1 arg1, T2 arg2);
void Publish<T1, T2, T3>(string key, T1 arg1, T2 arg2, T3 arg3);
```

`Action` 使用 `System` 中的委托类型。注册不返回 `IDisposable` 或其他注销句柄；消费方使用可稳定配对的方法回调，在所属生命周期结束时显式注销，不推荐匿名回调。

GameSDK 在包内消费同一事件总线，不依赖 GameHub；包级依赖遵循 [GameSDK 接入约定](../../README.md#依赖与程序集)。

## 行为与验收

| 情境与前提 | 要求与可判定结果 |
|---|---|
| 四组参数数量 | 无参、1 参、2 参、3 参均能成对注册与注销，并收到对应发布参数；同一事件支持多个监听分别调用 `Subscribe` 注册，各自接收并分别注销，不同事件互不串扰。 |
| 非法回调与重复注册 | `Subscribe`、`Unsubscribe` 均不接受 `null` 回调，即使事件尚未创建或已经没有监听也须报错；同一事件重复注册同一回调时报错，原监听仍只保留一份。 |
| 监听生效时间 | 注册成功后立即可接收消息；注销成功后不再接收，包括正在分发但尚未调用的监听。已进入执行的回调不要求回滚。注销后可重新注册同一回调，后续消息只接收一次；派发中重订遵循下方事件与回调规则。 |
| 监听抛出异常 | 每条监听独立 `try/catch`，通过日志报告异常并继续其他有效监听；不在分发结束后聚合抛出。 |
| 显式配对与生命周期 | 消费方可用同一方法回调完成注册和注销，注销针对注册时所属总线实例。总线生命周期结束时释放持有的监听；旧引用、未结束分发及延期清理不得影响后续有效实例。初始化、释放和按需重建遵循 [Singleton 需求](../../Singleton/Docs/需求.md)的 AC-04、AC-05。 |
| 性能 | 注册、注销及发布均纳入验收，覆盖稳定发布和高频增删；提供可复现实测及分配数据，容量、负载和量化目标在实施前对齐，不能只以复杂度声明通过。 |

## 事件与回调规则

以下为已确认规则，纳入实现与验收。

| 情境 | 规则 |
|---|---|
| 未注册监听的注销 | 有效但未注册的回调注销无操作，与 `null` 回调非法严格区分。 |
| 派发中新订阅或重订 | 立即参与后续或嵌套发布，不追补当前已开始的消息；注销仍立即生效。 |
| 事件名与签名 | 拒绝 `null` 或空事件名，以 `StringComparer.Ordinal` 匹配。一个 key 对应一种参数数量及有序 `typeof(T)` 签名，首次成功订阅绑定，注销至零仍保留至本实例释放；签名冲突报错。未绑定 key 的发布无操作，不创建签名。 |
| 通道类型 | 按调用时显式指定或编译器推断的泛型 `T` 建立通道，不自动匹配基类、派生类通道，也不按参数运行时类型改选通道；不禁止 C# 合法的 [Action 逆变](https://learn.microsoft.com/en-us/dotnet/csharp/programming-guide/concepts/covariance-contravariance/variance-in-delegates)。DTO 按定义所属模块共享，跨程序集引用同一份类型定义，同名不同类型不兼容。 |
| 回调身份 | 使用 [Delegate.Equals](https://learn.microsoft.com/en-us/dotnet/api/system.delegate.equals)，比较实际委托类型及有序调用列表中的目标、方法；不比较委托对象的引用身份。同对象同方法且委托类型相同可重新构造后配对，不同对象同方法各自独立；逆变场景注销保持注册时的泛型参数和委托。 |
| 组合回调 | 每次 `Subscribe`、`Unsubscribe` 的 `callback` 调用列表必须恰有一项。通过 `+=` 或 `Delegate.Combine` 合并后含多项的委托抛 `ArgumentException`，即使各项指向同一方法也非法；不拆分、不部分注册或注销，不创建签名或影响已有监听。调用列表说明见 [Delegate](https://learn.microsoft.com/en-us/dotnet/api/system.delegate#remarks)。 |
| 调用失败 | `null` 回调抛 `ArgumentNullException`，其他参数错误抛 `ArgumentException` 系列异常，重复注册或签名冲突抛 `InvalidOperationException`；不以仅记录日志代替失败结果。上述失败不改变注册、签名或既有监听。监听执行异常仍按上表逐条捕获并继续，不与参数校验错误混同。 |
| 失效实例操作 | 旧实例的 `Subscribe`、`Publish` 抛 `InvalidOperationException`；旧 `Unsubscribe` 仅清理所属实例且可幂等，仍校验回调输入。这些操作不能重新激活实例、积累监听或影响新实例，不另增公开 API。 |
| 分发与线程 | 同步按注册顺序分发，限定 Unity 主线程调用；单例创建线程不能自动视为 Unity 主线程，须接入可信校验入口。 |

字符串不再具有枚举类型的键隔离，建议事件拥有模块维护带模块前缀的字符串常量，如 `Inventory.ItemChanged`，避免同名同签名串扰。

模块入口：[EventBus](../README.md)。
