## 接口与实施方案

三个类均为 `GameSDK` 命名空间下的 `public static` 类，API 采用中文 XML 注释描述参数、行为、返回值和异常。`UtilsPath` 通过 `UnityEngine.Application` 取得根路径；`FileRead` 与 `FileWrite` 只依赖 .NET 标准库，不引用 `UtilsPath` 或 Unity 类型。

### 路径、编码及失败边界

1. `UtilsPath.CombinePath` 按 `Path.Combine(paths).Replace('\\', '/')` 执行；不做路径 `Trim`，不另加空白、URI 或越界验证，也不添加 `file://`。`Path.Combine` 对当前平台根路径的识别发生在分隔符替换之前；后续根路径按标准库规则重置前缀，不限制在首段目录内。
2. 读写类的路径参数直接沿 `System.IO` 本地路径规则处理，不调用自定义路径验证器，不做 URI 解析或转换，也不保证所有 URI 字符串必定抛错。路径无效和 I/O 失败保持标准库的异常行为，不捕获后降级为空值或成功结果。
3. 写入内容、字节数组或行集合为 `null` 时，在任何目录或文件副作用前抛 `ArgumentNullException`。行集合必须先完整物化，之后才能创建父目录或打开目标文件；枚举异常原样抛出且不改变目标。
4. 文本写入使用 UTF-8 无 BOM 和标准替换策略；文本读取使用 UTF-8 默认编码并启用 BOM 检测，可识别标准 `StreamReader` 支持的 Unicode BOM。文本和行追加仍按 UTF-8 写出，调用方须保证已有文件为 UTF-8，不会按已有 BOM 转码。读写类各自持有私有只读的 `UTF8Encoding(false)`，不新增共享编码类。空内容有效。
5. 文件流只在单次调用内存活，使用 `using` 等可靠清理保证正常及异常路径均释放；结果全部在流关闭前物化。写入父目录的创建逻辑作为 `FileWrite` 的私有方法集中维护，纯文件名的空父目录直接跳过。

### UtilsPath

| API | 约定 |
|---|---|
| `string CombinePath(params string[] paths)` | 按上述规则组合并统一分隔符；数组或任一元素为 `null` 时沿 `Path.Combine` 抛 `ArgumentNullException`，零元素返回空串，空段忽略，空白段原样交由标准库处理。保留 `jar:file://`、`http://`、`https://` 等已有前缀，不作 URI 编码或解析。 |
| `string StreamingAssetsPath { get; }` | 每次访问直接返回 `Application.streamingAssetsPath` 当前值，不缓存、不修改前缀或分隔符。 |
| `string GetStreamingAssetsFilePath(params string[] paths)` | 将 `StreamingAssetsPath` 作为首段，后接调用方给出的相对子路径，再按 `CombinePath` 规则组合；零参数返回根路径的统一分隔符形式。数组或元素为 `null` 时抛 `ArgumentNullException`。 |
| `string PersistentDataPath { get; }` | 每次访问直接返回 `Application.persistentDataPath` 当前值，不缓存、不修改前缀或分隔符。 |
| `string GetPersistentDataPath(params string[] paths)` | 将 `PersistentDataPath` 作为首段，后接调用方给出的相对子路径，再按 `CombinePath` 规则组合；零参数返回根路径的统一分隔符形式。数组或元素为 `null` 时抛 `ArgumentNullException`。 |

公开成员仅上述五项。两个根路径拼接方法要求调用方传入相对子路径，不另建验证器；若传入平台根路径，仍会发生 `Path.Combine` 的前缀重置，不提供根目录越界保护。字符串组合成功不表示该路径可由 `System.IO` 访问；尤其 StreamingAssets 的实际访问方式由调用方根据 Unity 平台处理。

### FileRead

| API | 约定 |
|---|---|
| `string ReadText(string path)` | 完整读取文本并进行 BOM 检测，返回不包含 BOM 的字符串。 |
| `byte[] ReadBytes(string path)` | 完整读取原始字节；使用标准库完整读取能力，不假定一次流读取即可读满。 |
| `string[] ReadLines(string path)` | 完整读取全部行并检测 BOM，结果不包含行终止符；空文件返回空数组，遵循标准按行读取对末尾换行的处理。 |

读取缺失文件必须抛出标准缺失异常，不能返回空值或已读取的部分内容。

### FileWrite

| API | 约定 |
|---|---|
| `void WriteText(string path, string content, bool append = false)` | 内容 null 检查后建立缺失父目录，默认覆盖或创建，`append` 为真时追加或创建；UTF-8 无 BOM。 |
| `void WriteBytes(string path, byte[] data, bool append = false)` | 数据 null 检查后建立缺失父目录，默认覆盖或创建，显式追加时保留已有字节。 |
| `void WriteLines(string path, IEnumerable<string> lines, bool append = false)` | 集合 null 检查后先将全部输入物化，枚举失败不得创建目录或改变目标；然后建立父目录并仅打开一次写入流。每个元素写为一行，`null` 元素按空行，每行追加 `Environment.NewLine`；不主动修补已有文件末尾缺失的换行。空集合在覆盖模式建空文件或清空，追加模式不改已有内容但可创建空文件。 |
| `void Create(string path, bool overwrite = false)` | 建立缺失父目录和空文件；默认已有文件时抛 `IOException` 且保留内容，显式覆盖时清空已有文件。 |
| `void Clear(string path)` | 仅截断已有文件为零字节，保留文件；不建立目录，文件或父目录缺失时抛标准缺失异常。 |

底层实现优先组合 `System.IO` 成熟 API，避免额外公共抽象。删除原 `UtilsPath` 的父目录提取、存在判断、目录创建、复制、文件/目录删除接口和自定义路径校验，不将这些公开操作转移到其他类。不保证目录创建回滚、写入原子性、多个调用方并发修改相同路径或跨平台 StreamingAssets 读取。

## 验证预期

必要静态检查包含：`UtilsPath` 仅保留约定的五个公开成员，读写类不引用它或 Unity 类型，已删除接口及自定义路径校验无残留引用；范围与依赖正确，全部 `.meta` GUID 唯一、无缺失且既有 GUID 保留，需求及 Task 链接可解析；独立 Agent 对照本文审查实现、测试及失败与重复操作闭环。

必要读写测试使用真实临时文件和真实 API，测试夹具每个用例建立唯一临时目录，收尾删除；采用项目实际 NUnit 版本支持的 `Parallelizable(ParallelScope.None)` 保持串行，修改当前目录时在 `finally` 恢复。不修改项目资源，不向 `Application` 返回的路径写入文件。覆盖：

- 中文文本、空文件、任意字节、UTF-8 无 BOM 输出及含 BOM 输入；读取结果完整、行分隔符合约定，空文件与缺失文件可区分。
- 文本、字节、行的覆盖和追加；行写入空元素、空集合，追加不主动补换行；创建默认不覆盖、显式覆盖，清空缺失文件不创建。
- 只有文件名的相对路径以及缺失父目录；路径参数错误沿标准库语义，不再保留统一空白/URI 拒绝测试。
- `null` 内容/字节/行集合及中途抛异常的行枚举，不破坏已有文件且不建立新父目录。
- 成功及失败后可再次以独占模式打开或删除文件，确保流已释放。
- 路径组合覆盖反斜杠统一为 `/`、零参数、空段、空白段、数组和元素 null、原生根路径重置前缀、多层子路径、Unicode 与空格；`jar:file://`、`http://` 和 `https://` 前缀保留，不添加 `file://`、不编码空格。
- 在 Unity EditMode 中将两个属性与真实 `Application` 对应值比较；两个根路径拼接方法覆盖多层相对子路径、Unicode 与空格、空段、零参数返回统一分隔符的根，以及 null 参数异常。相关用例标记 `[Category("UnityPath")]`，只比较路径，不创建或改动这些根下的文件。
