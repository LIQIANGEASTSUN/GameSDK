# 文件路径与读写需求

为 GameSDK 及引用本包的消费者提供 Unity 常用路径组合与同步本地文件读写，采用 `UtilsPath`、`FileRead`、`FileWrite` 三个静态直接 API，命名空间为 `GameSDK`。遵循 [GameSDK 框架规范](../../../README.md)、[Agent 协作协议](../../../../../Docs/Project/04_Agent协作协议.md)、[工程实施与验收标准](../../../../../Docs/Project/05_工程实施与验收标准.md)、[文档组织规范](../../../../../Docs/Project/06_文档组织规范.md)及[模块组织与交付规范](../../../../../Docs/Project/08_模块组织与交付规范.md)。

## 职责与边界

- `UtilsPath` 只负责路径组合、读取 Unity 的 StreamingAssets 与 PersistentData 路径，以及在这两个根路径后拼接调用方提供的相对子路径。不提供存在判断、父目录提取、复制、删除或独立目录管理 API。
- 路径组合按当前平台 `Path.Combine` 规则执行后，将反斜杠统一为 `/`；保留 Unity 返回的 `jar:file://`、`http://` 等前缀，不自行添加 `file://`，不拒绝、解析或编码 URI，不保证路径被限制在指定根目录内。
- `FileRead` 负责文本、完整字节和全部行读取；`FileWrite` 负责文本、字节、批量行的覆盖或追加，以及文件创建和清空。两类按 `System.IO` 本地路径语义工作，支持只有文件名的相对路径，不依赖 `UtilsPath` 或 Unity 类型，不将 URI 转换为可访问文件路径，也不另行保证 URI 输入必定抛错。
- 文本默认写出 UTF-8 无 BOM，读取时检测 BOM，非法文本沿标准编码替换策略处理。每次方法调用负责打开和释放全部流，读取结果已经物化；调用方无须持有对象或手动关闭。I/O 失败由异常表达，不记录日志并吞掉异常，不返回空内容或半份结果伪装成功。
- 不提供 MD5、StreamingAssets 网络读取、构建目录约定、自动处理 `.meta`、长期持有的写入流或接口适配层。普通写入不承诺 I/O 失败时原子保留旧文件、并发写入安全或已建目录回滚。

## 行为与验收

| 场景 | 要求与可判定结果 |
|---|---|
| 路径组合 | 多段路径按 `Path.Combine` 组合后统一为 `/`；零段返回空串，空段忽略，空白段保留标准行为，后续根路径可重置前缀，不自定义 URI 拒绝规则。 |
| Unity 根路径 | 两个属性分别直接返回 `Application.streamingAssetsPath` 和 `Application.persistentDataPath` 当前值；两个根路径拼接方法在根后拼接相对子路径，无参数时返回统一分隔符的根路径。 |
| 中文、空内容和二进制文件读写 | 文本、字节及行内容可完整读取；空文件属于合法成功结果，与文件缺失异常可区分。 |
| 覆盖、追加与批量行 | 默认覆盖、显式追加；批量行仅打开一次写入流，保留输入顺序，空行元素按空行写出。追加不主动补齐原文件末尾缺失的换行。 |
| 创建和清空 | 创建默认保护已有文件，显式覆盖才清空；清空保留已有文件，文件不存在时失败，不隐式创建。 |
| 输出父目录不存在或只传文件名 | 写入和创建自动建立目标父目录；只有文件名时直接使用当前目录，不尝试建立空目录。 |
| 数据为 null 或行枚举失败 | 写入数据的 null 检查在目录创建、文件截断等副作用前执行；批量行先完整枚举，失败不改变目标文件，不建立目标父目录。路径错误沿标准库语义处理。 |
| 调用返回或抛出异常 | 文件资源已释放，消费者可继续打开、移动或删除文件。 |

## 用法

消费者直接调用静态方法，不需要初始化和注册。例如由 `UtilsPath.GetPersistentDataPath("Save", "profile.json")` 取得保存路径，再以 `FileWrite.WriteText` 保存文本，之后用 `FileRead.ReadText` 读取。`GetStreamingAssetsFilePath` 只负责取得路径；消费者需按实际运行平台决定如何读取，返回 URI 不代表同步文件 API 能访问。调用方在自己的业务边界处理异常与日志。具体接口、失败语义及验收入口见 [实现文件路径与读写](Tasks/实现本地文件工具.md)。
