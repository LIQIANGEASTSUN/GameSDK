## 实现契约

命名空间 `GameSDK`，基类 `public abstract class SingletonMono<T> : MonoBehaviour where T : SingletonMono<T>`。`Instance`、`ReleaseInstance()`、`OnInitialize()`、`OnRelease()` 的签名及具体类型／构造约束见[普通类契约](实现普通类单例.md#实现契约)；创建由 Unity 负责，构造及字段初始化不访问 Unity API、不取得需回收资源。

使用方通过 `具体类型.Instance` 获取，通过 `具体类型.ReleaseInstance()` 释放；具体组件按上述契约以自身为 `T` 并提供 private 无参构造，由 Unity 创建，不直接 `new`。

由调用方保证仅在 Unity 运行期主线程获取，退出时停止获取；生命周期方法均在主线程同步执行，释放负责收尾。编辑或退出期获取不在支持范围，框架不检查 `Application` 的运行或退出状态，也不加线程同步。组件创建、初始化与释放按本 Task 独立实现，不沿用普通类的锁。构造、`OnInitialize`、`OnRelease` 须同步完成，不使用 `async void`，不得直接或间接调用同类型的 `Instance`／`ReleaseInstance`；这些操作期间同步触发的 `Awake`、`OnEnable` 和日志回调也须遵守此约束，操作完成后的正常获取不受影响。这是调用方约束，不设置忙碌状态或检测非法重入。框架只占用 `OnDestroy`，派生类不得遮蔽；派生类可使用 `Awake`，但它在本轮创建激活中触发时仍遵守非重入约束。禁用不释放，不调用 `DontDestroyOnLoad`，不限制宿主层级。

唯一框架字段是静态 `_instance`，不增加实例字段、生命周期标记、宿主所有权标记、队列或替代状态。创建期间只用局部宿主引用和候选引用记录本轮需清理的对象。框架只创建并管理自己的组件和整个宿主，不扫描、复用或接管预置／手工组件，不为这些外部组件自动初始化或销毁。

## Unity 生命周期实现

1. **获取与创建**：已有有效 `_instance` 就直接返回；否则在一个创建方法中完成构造校验、创建、初始化及失败清理，不另设检查中转方法。类型须非抽象、具有 private 无参构造且没有 public 构造。先在创建流程的 `try` 外构造名称为类型名的 GameObject，构造失败自然向外抛出；随后在 `try` 内将宿主设为非活动，再 `AddComponent<T>` 并保存候选。不查找场景对象、不接管同类型预置组件，也不保留扫描、排序、去重或退役流程。
2. **初始化与失败**：取得候选后直接调用 `OnInitialize`，随后激活宿主；最后只检查一次候选仍有效且宿主 `activeInHierarchy = true`，全部成功后创建方法返回，`Instance` 才写入 `_instance`。若组件被同步销毁、宿主挂在非活动父级下，或 `Awake`／`OnEnable` 立即停用宿主，未满足此条件就抛 `InvalidOperationException` 并按创建失败处理；中途 Unity API 抛出的异常也进入同一失败处理。失败时尚无登记，只在已取得非空托管候选时调用一次 `OnRelease`，即使其 Unity 原生对象已销毁也须补清理；没有取得候选则不调用释放钩子。不保留初始化开始标记，也不在每一步重复检查候选。失败收尾在 `finally` 直接销毁局部宿主；[Unity Destroy](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Object.Destroy.html) 对已销毁对象安全。单个异常保留原栈；原始失败与清理均报错时，用 `AggregateException` 按原始、清理顺序保留二者，下次获取可重试。
3. **Awake 与外部组件**：基类不实现 `Awake`，不会因场景加载、激活或手工 `AddComponent` 自动登记或执行单例钩子。框架候选在激活后由 Unity 调用派生 `Awake`／`OnEnable`，此时 `OnInitialize` 已完成，但候选尚未登记；这些回调不得重入同类型入口。预置、隐藏、非活动、手工添加或错误二次派生的外部组件均不接管、不初始化、不自动销毁；其生命周期由使用者负责。
4. **显式释放**：`ReleaseInstance` 捕获当前实例和它的 `gameObject`，先将 `_instance` 清空，再调用 `OnRelease`，最后在 `finally` 销毁捕获的整个宿主；异常直接向调用方传播。不获取或创建替代者，空登记重复释放无操作。清理只使用捕获对象，释放后同帧获取可以创建新实例，旧宿主的延迟销毁不影响新登记。
5. **OnDestroy**：仅当 `ReferenceEquals(_instance, this)` 时清理，旧对象及未登记组件直接返回。先取得当前 `gameObject`，再撤销登记、调用 `OnRelease`，最后回收该宿主；因此外部只销毁组件也不会遗留框架创建的空宿主。原生回调捕获异常并用 `Debug.LogException` 报告，不再次 `Destroy(this)`。初始化／激活中候选被同步销毁时尚未登记，此回调不提前清理，由创建调用栈在复核失败后清理一次；显式释放已撤销登记，后来的 `OnDestroy` 同样不重复清理。

已发布实例必经过宿主实际激活，不再支持从未激活预置对象的失效补清理，也不为此增加标记或轮询。成功获取后使用者仍可禁用或调整宿主层级，不触发重新初始化；实际激活要求只在首次成功发布前检查。外部 `Destroy` 为延迟销毁，在实际失效或收到通知前，不承诺检测到排队请求。框架自建宿主整体归框架管理，使用者决定其场景及保留期限；框架不干预其他宿主。

## 验证

静态检查构造、框架消息、同步非重入约束及程序集隔离。PlayMode 测试使用真实组件与钩子计数，覆盖类型隔离、失败、幂等及自动引擎回调；公共入口非法重入属于调用方违约，不以忙碌异常作为验收。具体包括：

| 触发 | 预期 |
|---|---|
| 首次获取、重复获取、再获取另一类型 | 首次创建一个非活动宿主并初始化，激活和复核成功后才返回；同类型复用，不同类型互不影响。 |
| 场景已有活动／非活动／隐藏／错误二次派生组件，再通过 Instance 获取 | 始终另建框架实例；外部组件不登记、不执行单例钩子、不被销毁，释放框架实例不影响它们。 |
| 构造契约非法、宿主创建失败或 AddComponent 未取得托管候选 | 无成功登记，不调用释放钩子；若已创建宿主则销毁。 |
| 初始化取得部分资源后报错；初始化／激活中对象同步失效 | 清理一次、无登记及自建宿主遗留；原始与清理异常均报告，之后可重试。 |
| 初始化中挂到非活动父级；OnEnable 立即停用宿主 | 激活结束后 `activeInHierarchy = false`，创建抛错并清理一次、销毁本轮宿主，不删除外部父级，后续获取可重试。 |
| 派生 Awake／OnEnable 在创建激活中执行 | OnInitialize 先完成，基类不自动接管或再次初始化；回调不重入同类型入口。 |
| 主动释放后同帧再获取，随后旧 OnDestroy 到达 | 旧实例仅清理一次，新实例有效，旧回调不移除新登记；未登记的外部组件销毁同样无影响。 |
| 外部销毁当前组件或整个宿主；释放钩子报错 | 清理一次且清空登记；只销毁组件时仍回收自建宿主，异常不遗漏收尾。 |
| 禁用、切场景，使用者自行保留对象 | 禁用不释放；场景与保留由使用者决定，销毁时只处理框架自建宿主。 |

测试规划放在 `Core/Singleton/Tests/PlayMode/`，编辑生命周期验证按所需环境组织，均与运行时代码隔离；包测试发现与 manifest 配置见[普通类任务的测试接入](实现普通类单例.md#测试接入)。后续实现须提供下列验证的可复现入口，由用户在宿主 Unity 中执行，实际选中全部目标用例并通过且无编译错误为预期：

1. Test Runner → PlayMode，运行覆盖上述组件、资源与场景行为的用例。
2. Test Runner → EditMode，验证外部 `ExecuteAlways` 编辑对象不被登记、初始化或销毁；不在编辑模式调用 `Instance`。

同步失效场景应以受控方式注入初始化／激活中的对象失效，并验证自建宿主下一帧无遗留、替代实例有效；另行覆盖普通延迟销毁与下一帧收尾，不能用同步失效代替延迟销毁验证。
