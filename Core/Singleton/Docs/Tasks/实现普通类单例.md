## 实现契约

命名空间 `GameSDK`，基类 `public abstract class Singleton<T> where T : Singleton<T>`。

| 入口 | 语义 |
|---|---|
| `public static T Instance { get; }` | 全程持锁，按需创建、初始化，返回就绪实例；并发调用等待，失败抛错，不返回半成品。 |
| `public static void ReleaseInstance()` | 全程持同一锁，仅释放取得锁时的当前实例，不调用 `Instance` 或触发创建。 |
| `protected virtual void OnInitialize()` | 创建后调用一次，取得实例资源。 |
| `protected virtual void OnRelease()` | 释放实例资源，含初始化失败前已取得者。 |

具体类以自身为 `T`，实例的实际类型必须恰为 `T`；类型非抽象、private 无参构造且无 public 构造，基类 protected 构造。首次创建先校验构造合约，再受控反射创建，不用 `new()` 约束。泛型基类无法在编译期强制派生类私有构造，仍须静态检查具体类型。构造与字段初始化不得获取需回收的外部资源。

### 最小用法

```csharp
using System.Collections.Generic;
using GameSDK;

public sealed class SessionCache : Singleton<SessionCache>
{
    private SessionCache() { }

    public Dictionary<string, int> Values { get; private set; }

    protected override void OnInitialize()
    {
        Values = new Dictionary<string, int>();
    }

    protected override void OnRelease()
    {
        Values?.Clear();
        Values = null;
    }
}

// 在使用方的进入／退出边界调用：
// SessionCache.Instance.Values["Count"] = 1;
// SessionCache.ReleaseInstance();
```

## 生命周期实现

每类型独立维护实例引用及一把锁，不使用生命周期枚举、释放标志或等价状态标记。同类型的创建、初始化、失败清理和正常释放全过程持同一锁；并发入口等待取得锁后按最新实例处理，不因另一个线程正在构造或执行钩子而抛忙碌异常。已释放对象不再登记，下轮获取新建；业务并发及旧引用使用由消费方负责。

1. **获取**：`Instance` 的整个 getter 在锁内执行；`null != _instance` 时直接返回已有实例，否则在平铺的 `try` 中执行 `_instance = Construct()`，失败由 `catch` 将 `_instance` 清空并原样抛出，最后返回 `_instance`。`Construct()` 在一个方法内完成构造校验、反射创建、初始化及失败清理；使用 [`BindingFlags.DoNotWrapExceptions`](https://learn.microsoft.com/en-us/dotnet/api/system.reflection.bindingflags) 保留原构造异常，不再手动解包。反射创建位于初始化的 `try/catch` 之外，构造失败不调用释放钩子，初始化成功才返回局部对象。
2. **释放**：`ReleaseInstance` 在同一锁内判空，为空直接返回；否则在 `try` 中调用当前实例的 `OnRelease`，在 `finally` 中清空登记，不因钩子报错遗漏收尾。顺序或并发的重复释放不创建实例；等待者取得锁后若登记已空则无操作，若有其他获取已创建新实例则释放当时的最新实例，每个实例清理一次。
3. **失败**：构造失败不调用释放钩子；一旦进入初始化钩子，失败须对局部对象尝试一次 `OnRelease`，整个过程仍在获取锁内。单个失败保留原始异常；初始化与清理均失败时，用 `AggregateException` 按原始、清理顺序保留二者。反射包装不替代构造原始异常；主动释放异常也在清空登记后抛出，下次获取可重试。等待中的获取可在前一次失败清理结束后重新创建；等待中的释放不主动创建。

构造、`OnInitialize`、`OnRelease` 必须同步完成，不使用 `async void`，也不得直接或间接再次调用同类型的 `Instance` 或 `ReleaseInstance`。这是调用方约束，不提供重入检测；C# 锁允许同线程重入，不能把锁当作这项防护。持锁执行期间不得等待需要取得同一单例锁的其他线程，避免死锁。

同类型操作由全程锁串行化，收尾直接处理本轮对象并清空登记，不经静态获取入口清理资源。具体类型负责逐项清理、不遗漏资源；框架不接管业务资源或使用期限；使用者先停止消费者再显式释放，跨 Play 生命周期也由使用者控制，不作自动会话重置。

## 验证

静态检查构造合约及程序集隔离；EditMode 测试观察具体单例的资源和钩子计数：

| 触发 | 预期 |
|---|---|
| 同类型连续获取，再获取另一类型 | 前者引用相同、初始化一次；类型间状态、资源、释放互不影响。 |
| 构造失败；初始化取得部分资源后失败 | 均无可用登记、可重试；前者不调释放钩子，后者清理一次、无资源遗留。 |
| 初始化与清理均报错；主动释放钩子报错 | 保留约定异常，均清空登记，不重复调用同一实例的释放钩子。 |
| 构造或初始化被可控钩子阻塞时，其他线程获取或释放 | 并发入口等待，不抛忙碌错误、不取得半成品；钩子结束后，获取复用完成实例，释放清理取得锁时的当前实例。 |
| 正常释放或初始化失败清理被阻塞时，其他线程获取或释放 | 清理期间不能创建新实例；清理结束后，获取按空登记新建，释放按取得锁时的最新登记处理。 |
| 构造和钩子的同步、非重入约束 | 静态检查不使用 `async void`，不直接或间接重入同类型获取／释放，不等待需要同一锁的线程；不把非法重入的运行结果作为框架防护验收。 |
| 空状态释放；成功释放两次后再获取 | 释放均不创建、旧实例仅清理一次；随后获取新实例，旧引用不影响新登记。 |

后续实现应为上述场景提供 EditMode 用例及可复现入口，由用户在宿主 Unity 的 Test Runner → EditMode 运行；应实际选中全部目标用例并通过，且无编译错误。目标使用 IL2CPP 或裁剪时，还须验证反射创建与非 public 构造保留。
