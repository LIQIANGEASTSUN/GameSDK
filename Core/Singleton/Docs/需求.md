# Singleton 需求

为 GameSDK 提供普通类与 Unity `MonoBehaviour` 两类单例的受控创建、初始化和释放，保证创建、唯一性与释放一致。包边界见 [GameSDK README](../../../README.md)。

| AC | 要求与验收 |
|---|---|
| AC-01 | 具体单例使用私有构造，不暴露 public 构造，消费方不能直接 new。 |
| AC-02 | 同类型获取复用唯一有效登记实例，不同类型隔离。普通类的构造、初始化、失败清理与释放全程持同一锁，并发调用等待后按最新实例处理；Mono 在主线程同步运行，不加锁。构造、初始化与释放钩子须同步完成，调用方保证不直接或间接重入同类型获取／释放入口，不检测非法重入；Mono 在这些操作期间同步触发的 Awake、OnEnable 及日志回调也遵守此约束。 |
| AC-03 | Mono 没有有效登记时只创建自己的 GameObject 和组件，完成初始化、激活及有效性检查，且宿主 `activeInHierarchy = true` 后才登记返回；未实际激活视为创建失败并清理。成功发布后仍允许使用者禁用或调整层级。不扫描场景，不复用预置组件，不通过 Awake 接管组件。非框架创建的同类组件不登记、不初始化、不自动销毁。调用方仅在 Unity 运行期主线程获取，退出时停止获取；生命周期方法均在主线程同步执行，释放负责收尾。编辑或退出期获取不在支持范围，框架不检查 Application 运行或退出状态。 |
| AC-04 | 提供显式释放入口及受保护的初始化／释放钩子。每实例初始化一次，成功才可用；一旦开始初始化，正常释放或初始化失败均清理一次。失败须报错并撤销框架登记，保留初始化与清理异常，后续获取可重试。 |
| AC-05 | 重复释放安全且不创建，下一次获取才可新建；已释放实例不复用，其框架收尾及迟到回调不得清除新登记或误释放新实例资源。 |
| AC-06 | 使用期限、跨场景保留由使用者决定，底层不干预宿主层级；Mono 对自己创建的宿主整体负责，释放时销毁该宿主，不清理其他宿主中的组件或资源。 |

Mono 只管理通过 `Instance` 完成创建的组件；预置和手工创建的组件及其生命周期由使用者自行管理。接口、状态、流程与验证见[普通类 Task](Tasks/实现普通类单例.md)和[组件 Task](Tasks/实现MonoBehaviour单例.md)，与本文共同作为实现和验收依据。
