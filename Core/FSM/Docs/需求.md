# FSM 需求

用纯 C#、同步、单线程的有限状态机管理互斥状态；宿主负责业务依赖和驱动。包边界见 [GameSDK README](../../../README.md)，实施方案与验证见[实现有限状态机](Tasks/实现有限状态机.md)。

机器通过 `AddState(StateBase state)` 注册状态、`ChangeState(int stateId, object data = null)` 立即选择或切换状态、`OnExecute(float deltaTime)` 驱动当前状态、`OnExit()` 退出当前状态、`OnRelease()` 释放注册状态。`Init()` 是退出当前状态并保留注册的重置入口，不是选态前的必需步骤。

## 行为与验收

- **归属：** 只使用非泛型 `StateMachine`、`StateBase`，状态标识由 `StateBase` 的公开只读 `int State` 提供。`StateMachine.NoState = -1` 表示无状态，保留此值且禁止构造或注册对应状态，其余 `int` 值均可作为状态标识。状态独占绑定机器，拒绝空状态、重复 ID/实例和仍绑定另一台机器的状态。注册不冻结；释放并解绑后，机器和状态均可重新使用。
- **切换：** 先验证目标已注册，再立即完成切换；业务在请求前检查条件和参数。无当前状态时只进入，来源为 `StateMachine.NoState`；普通切换依次退出旧态、设置新态上下文与当前引用、进入新态。退出回调内当前仍是旧态，进入回调内已是新态。同态无操作，不替换参数。状态通过无参 `OnEnter()`、`OnExit()` 和可读的 `From`、`To`、`Data` 获取上下文。
- **更新：** 时间必须有限且非负，每次只更新调用时的当前状态；无当前状态时无操作，进入不隐式更新。更新回调中的 `ChangeState`、`OnExit`、`OnRelease` 立即执行，状态发生变化后调用方应立即返回，避免继续使用已退出的资源；同态无操作后可继续执行。机器不继续更新新态，也不保存队列或限制转换次数。
- **重入边界：** `OnEnter`、`OnExit`、`OnRelease` 回调不得直接或间接调用本机的注册、重置、切换、更新、退出或释放入口，只可查询状态及管理自身资源。`OnExecute` 不得递归驱动本机。此约束由调用方遵守，机器不增加阶段标记检测非法重入；生命周期回调引发的后续流程由宿主在回调返回后显式执行。
- **退出与重置：** `OnExit()` 与 `Init()` 都退出当前状态、清空当前引用并保留注册；无当前状态时无操作，再次选态无须初始化。退出或释放时状态的目标为 `StateMachine.NoState`；普通切换退出收到实际目标。退出无论成功或失败，都清空该状态的 `Data`，状态自行管理额外保留的数据和资源。
- **异常：** 退出失败不进入目标，清空当前引用后向外抛出，机器仍可使用。进入失败时立即对部分进入的新态尝试一次退出，目标为 `StateMachine.NoState`，随后清空当前引用和 `Data`；补退也失败时同时报告原错误和清理错误，不回退旧态。更新失败直接抛出并保留抛出时的当前态，即使它已切换为新态，由宿主决定继续、退出或释放。无故障锁定，已发生的副作用不回滚。
- **释放：** 先尝试退出当前状态，再遍历全部注册状态分别调用一次 `OnRelease()`，包括未进入状态，不保证释放顺序。失败继续清理其余状态，最后统一清空 `Machine`、`From`、`To`、`Data`、注册表及当前引用，并报告错误；单个错误保留原堆栈，多个错误汇总。空机器重复释放无操作。状态负责清理自己拥有的资源及部分初始化或失败残留。

## 异步责任

Unity 宿主在主线程驱动和销毁。消费者每次进入生成新代次，退出开始或销毁时先失效再取消异步工作。结果回主线程后检查机器有效、当前状态和代次；失效结果仅归还资源。验收覆盖 A→B→A 的旧结果，不能仅检查当前状态或活跃标记。
