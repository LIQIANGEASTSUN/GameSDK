# 实现有限状态机

状态：`InProgress`。

## 产物与接口

按[需求](../需求.md)实现包内 `Core/FSM/StateMachine.cs`、`Core/FSM/StateBase.cs`，使用 `GameSDK` 命名空间及现有程序集。测试放 `Core/FSM/Tests/EditMode/`，独立 Editor 测试程序集引用 `GameSDK` 和 TestAssemblies；附齐元数据。

`StateMachine` 公开接口为：

```csharp
const int NoState = -1;
StateMachine();
void AddState(StateBase state);
void Init();
void ChangeState(int stateId, object data = null);
void OnExecute(float deltaTime);
void OnExit();
void OnRelease();
StateBase Current { get; }
```

`StateBase` 为抽象类，受保护构造 `StateBase(int state)` 固定公开只读 `int State`；`state` 为保留值 `StateMachine.NoState`（`-1`）时抛 `ArgumentOutOfRangeException(nameof(state))`，其余 `int` 值合法。`protected internal StateMachine Machine { get; internal set; }` 由机器绑定/解绑，包外派生类只读。派生类可读取 `protected int From`、`protected int To`、`protected object Data`，前两者初始为 `NoState`，数据初始为 `null`。机器通过仅做赋值的 `internal void SetFrom(int from)`、`internal void SetTo(int to)`、`internal void SetData(object data)` 设置上下文。

提供以下 `protected internal virtual` 回调，默认无操作，机器直接调用 `OnXXX`，不设 `Enter`、`Execute`、`Exit`、`Release` 中转方法；包外派生类使用 `protected override` 重写，同程序集使用 `protected internal override`：

```csharp
void OnEnter();
void OnExecute(float deltaTime);
void OnExit();
void OnRelease();
```

进入前设置 `From` 为旧态标识或 `NoState`、`To = NoState`、`Data` 为本次参数；退出前将 `To` 设为实际目标，普通退出或释放使用 `NoState`。退出后 `From`、`To` 保留最近上下文，`Data` 在退出的 `finally` 中清空；释放结束统一将 `From`、`To` 复位为 `NoState`。同态请求不改写这些值。状态自行管理额外保留的数据及业务资源。

## 实施顺序

1. 机器只持有 `Dictionary<int, StateBase>` 注册表及 `Current` 当前引用。注册时直接绑定 `Machine`，释放时直接解绑；不设 `Bind`、`DetachAfterRelease` 或永久已释放标记。取消注册冻结、初始化门槛、故障锁定、释放后禁复用、延迟终止和注册顺序释放规则，不保留请求结构、队列、转换次数上限、阶段枚举或等价控制标记。
2. 空状态抛 `ArgumentNullException`，重复 ID/实例或归属冲突抛 `InvalidOperationException`，未注册目标（包括 `NoState`）抛 `ArgumentException`，非法时间抛 `ArgumentOutOfRangeException`。这些检查先于状态变化。`Init()` 调用正常退出逻辑，只重置当前状态、保留注册，可重复；选态仅要求目标已注册。
3. `ChangeState` 验证目标后判断同态。普通切换先保存旧态标识，设置旧态 `To` 并直接调用 `OnExit()`，回调内 `Current` 仍是旧态；退出的 `finally` 清空 `Current` 和旧态 `Data`。退出成功才设置新态上下文及 `Current`，随后直接调用 `OnEnter()`。无当前态时来源为 `NoState`，不调用退出；进入不隐式驱动。
4. 进入回调抛错时，立即给该新态设置 `To = NoState` 并尝试一次 `OnExit()`，无论补退成功与否均清空 `Current` 和 `Data`；单独的进入异常用原栈向外抛出，补退也抛错时用 `AggregateException` 按原异常、补退异常顺序汇总。正常退出失败不进入目标；更新失败直接传播并保留当前态。这些失败均不锁定机器。
5. `OnExecute` 只调用一次当前状态。更新回调内允许立即切换、退出或释放，状态改变后调用方应随后返回，同态无操作后可继续；禁止递归 `OnExecute`。更新回调在切换后再抛错时保留抛出时的当前态，不回滚。`OnEnter`、`OnExit`、`OnRelease` 内禁止直接或间接调用本机 `AddState`、`Init`、`ChangeState`、`OnExecute`、`OnExit`、`OnRelease`，只可查询和清理资源。这个非重入约束由调用方遵守，不声称机器会检测或抛错；后续业务流程由宿主在回调结束后显式调用。
6. `OnRelease` 先尝试退出，再遍历注册字典的全部状态调用 `OnRelease()`，不保证顺序，逐条失败后继续。所有释放回调尝试完毕后，统一清空各状态的 `Machine`、`Data`，把 `From`、`To` 复位为 `NoState`，再清空字典和 `Current`；中途仍保留关联供清理使用。单异常保留原堆栈，多异常用 `AggregateException` 汇总。空机器释放无操作，解绑后的状态可重新注册。释放回调须能清理未进入状态及部分初始化残留；没有额外队列、注册顺序列表或快照列表。
