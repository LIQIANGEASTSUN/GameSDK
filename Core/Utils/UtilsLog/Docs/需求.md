# UtilsLog 需求

用户目标：为允许引用 GameSDK 的消费者，用静态类和静态方法封装 Unity 日志，支持输出开关与级别控制。模块直接依赖 Unity；包边界见 [GameSDK README](../../../../README.md)。

本需求定义职责、行为与验收；公开接口、实施方案和调用示例见[实施任务](Tasks/实现Unity日志封装.md)。需求与 Task 共同构成实现规范，源码和测试是按规范交付的产物。

## 行为与验收

| 情境与前提 | 要求与可判定结果 |
|---|---|
| 调用与配置 | 通过静态类 `UtilsLog` 的静态方法输出和配置，无需实例、组件或显式初始化；模块持有一份供所有消费者共用的配置。 |
| 开关与等级 | 采用 `Info < Warning < Error` 最低阈值，关闭时连异常也不转发，组合见下表。设置非法等级抛 `ArgumentOutOfRangeException`，配置不变。 |
| 运行时修改 | 各构建类型均可反复修改，完成后对后续调用生效；重新开启保留阈值，不缓存或补发被过滤日志。 |
| 初始状态与会话 | 静态字段初始化为开启、阈值 `Info`，模块不设置 Play 会话重置钩子。启用 [Domain Reload](https://docs.unity3d.com/6000.0/Documentation/Manual/domain-reloading.html) 时随脚本域重新初始化；关闭时保留当前配置。宿主需要每次 Play 使用固定配置时显式设置开关与等级，模块不按构建类型改写策略。 |
| 普通日志 | `Log`、`Warning`、`Error` 均只接收一个 `string message` 参数，分别将原字符串交给 `Debug.Log`、`Debug.LogWarning`、`Debug.LogError`；`Log` 对应 `Info` 等级。保留级别，不加前缀、改写或额外格式化；`null`、空字符串沿用 Unity 语义。 |
| 异常报告 | 按 `Error` 过滤，将原异常和可选上下文交给 `Debug.LogException`，保留类型、原始堆栈及上下文对象定位。空异常始终抛 `ArgumentNullException`，不受开关影响。 |
| 输出过滤 | 每次输出读取本模块当前开关与阈值并判断，被过滤时不调用 Unity 输出；不缓存输出判定。传参前已发生的字符串插值、拼接或构造不在过滤保证内。 |
| 输出边界与失败 | 只控制本模块入口，不修改 Unity 的 `logEnabled`、`filterLogType` 或全局处理器，不影响其他直接日志。Unity 全局配置及 Console 过滤仍可影响可见性；放行不保证显示。底层抛错原样传播，不通过自身入口递归报告。 |

“输出”指包装层放行并转发 Unity：

| 总开关 | 最低级别 | Log（Info 级别） | Warning | Error / Exception |
|---|---|---|---|---|
| 关闭 | 任一合法级别 | 不输出 | 不输出 | 不输出 |
| 开启 | Info | 输出 | 输出 | 输出 |
| 开启 | Warning | 不输出 | 输出 | 输出 |
| 开启 | Error | 不输出 | 不输出 | 输出 |
